# Independent map design, accessibility and performance audit

Reviewer: delegated Codex design audit agent. This report covers the MapLibre / Three neighborhood implementation added after the original Helio audit. The reviewer owns only `src/map.css` and this evidence; map behavior and geometry corrections were made by their respective owners. The earlier horizon-only report remains separate in `audit-design.md`.

## Scope and evidence

The audit uses actual OpenFreeMap traffic through Chromium desktop automation at mobile CSS widths. Initial development checks ran at `http://127.0.0.1:5188/helio/`; targeted stable-production checks run at `http://127.0.0.1:5196/helio/`. Normal UI screenshots, aggregate request/draw counts, control outcomes and model-part counts are saved under ignored `qa-private/map-design/` and `qa-private/map-design-final/`. No provider tiles, HAR, raw building GeoJSON or feature collections are persisted by these QA scripts.

The reviewer inspected the rendered page and screenshots; the source reference videos were not viewed by this reviewer. This is not a physical-phone test, native Safari test, assistive-technology certification or complete WCAG conformance claim. The 200% test doubles computed font sizes; it is not native browser zoom. Draw counts are WebGL calls, not FPS or battery measurements.

## Findings and corrections

1. **Resolved — desktop composition retained an obsolete two-column grid.** The map occupied only about 912 px of a 1296 px content area; search and view controls inherited narrow columns. CSS now spans the map stages across the editorial grid, retaining heading/readout as the opening row. Actual 1440 px captures show the full-width map and search stage.
2. **Resolved — mobile labels, build control and attribution needed reflow.** CSS permits wrapping, makes the build control fit the viewport, raises functional caveat text to 12 px and provider attribution to 11 px, and reserves separate corners for attribution and scale. Actual RU/EN screenshots and bounds checks at 320/360/390/768/1440 show no offscreen controls or horizontal overflow.
3. **Resolved — time control was too far below the map.** The application owner added a map-local timeline immediately below the canvas; this reviewer styled it as an integrated stage with local time, offset, altitude and azimuth. Runtime tests confirm keyboard changes synchronize it with the retained planner timeline. Mobile uses a vertical map → time → model actions sequence.
4. **Resolved — valid WebGL map could show an unavailable message after StrictMode cleanup.** The map owner added disposed guards to the context-loss/error handlers. Fresh actual-provider contexts show the map ready and usable, with no false unavailable state.
5. **Improved with an accepted framing tradeoff — initial tilted neighborhood was a postage stamp.** The map owner reduced camera padding and increased the fitted zoom. Actual mobile captures show a prominent neighborhood and its dashed 300 m extent. Some near/side boundary segments can reach or cross the canvas edge after the additional zoom; the model is identifiable, but this is not a claim that every boundary vertex stays in frame at every selected point.
6. **Resolved — offscreen time changes redrew the map.** The initial interaction instrumentation measured 489/711 WebGL draw calls when the map was moved offscreen and time changed. The map owner added IntersectionObserver/document-visibility gating and conditional custom-layer repaint. The final candidate records **zero offscreen time-change draw calls** at both widths, then correctly redraws with the current sun state when returned to view.
7. **Improved — roof/wall tones merged.** The ShadowLayer owner added cream caps, slightly darker side materials and a modest directional-light increase while retaining solar direction and geometry. Actual final 390/1440 screenshots show more distinct roofs and vertical faces. The restrained colors still resemble an architectural model; they do not imply surveyed surfaces or true material appearance.
8. **Implemented and verified — first-screen map CTA.** The application owner added an anchor to `#map-stage`; CSS gives it a warm underline, a 44 px minimum target and pointer input within the hero. The rendered target is 47 px high and wholly visible at RU1165×747 and RU/EN390×844. Tab reaches it from the language control; Enter scrolls to the map. At both tested mobile languages, the canvas and map-local timeline are visible together after the jump.

## Measured results

- Ten valid RU/EN viewport cases at 320/360/390/768/1440 px: zero selected axe WCAG A/AA violations, zero JavaScript page errors, no horizontal overflow and no controls outside the viewport. All show visible `OpenFreeMap © OpenMapTiles Data from OpenStreetMap` attribution. The initial development-server 320 px text200 snapshot was discarded because an HMR update reset the locale and unmounted the map during QA; it is not counted.
- Two deliberate failure cases at 390 px: no-WebGL and provider network abort. Both preserve working local solar time controls and give an honest unavailable state. Open horizon remains available; no-WebGL uses its genuine 2D schematic fallback.
- Thirty-four interaction assertions passed: 17 each at 390 and 1440 px. Tests actually used offline city search with Tab/Enter, unknown-city feedback, map keyboard pan plus map-centre selection, selected-zone preservation, zoom buttons, real-provider neighborhood build, keyboard local timeline, synchronized planner timeline, night status, north/flat/pitched views, additional horizon mode and its 2D control. Fresh contexts have no automatic localStorage entry. Both actual-provider builds had 151 contour parts and `incomplete=false` at the tested shifted London point.
- Initial runtime for those builds: zero draw calls during 700 ms idle, zero idle provider requests, zero provider requests during time changes. A visible change caused 489 calls at 390 px / 711 at 1440 px; offscreen changes caused the same counts. These pre-fix results are retained as evidence of the resolved performance finding.
- **Final candidate: 44 control/runtime assertions passed**, 22 at each of 390/1440 px. Actual models again have 151 contour parts and `incomplete=false`; there are no JavaScript page errors. The two-material model produces 790/1013 WebGL calls for a visible time update, **zero draws during 700 ms idle**, **zero idle/provider time-change requests**, **zero offscreen time-change draws**, and 790/1013 calls on visible return. These are draw calls across normal/shadow passes, not rendered frames. The additional material improves depth while increasing per-update draws; the application remains on demand.
- **Final candidate: 55 stress/reduced-motion assertions passed** across RU320 text200, EN390 reduced motion and RU1440 reduced motion, with zero selected axe violations, page errors or console errors. Locale, map presence and doubled fonts remain intact before/after axe. Effective map DPR is capped at 1.5. Controls fit, attribution remains within the canvas, keyboard time changes synchronize both timelines, and reduced-motion contexts still build an actual complete model.
- **Final candidate: 26 first-screen/anchor assertions passed**, covering RU1165×747 and RU/EN390×844. The actual CTA and post-jump map screenshots were visually inspected.
- A tall element screenshot appeared to show the skip link. Direct DOM probes and final explicit assertions establish that the unfocused RU320 text200 link is fully hidden (top −90, bottom −25), the focused link fits (top 10, bottom 75), and Enter reaches `#planner`. The suspected finding was withdrawn; no product change was made based on a screenshot artifact.
